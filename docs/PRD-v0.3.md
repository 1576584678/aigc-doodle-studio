## 二、背景与目标

### 2.1 背景

v0.2 已完成一条完整但封闭的链路：用户填写 API Base URL / Key / Model → 选择简笔画或火柴人 → 输入描述 → 模型返回 SVG → 白名单过滤 → 画布渲染 → 下载 SVG / 复制代码 / 存入本地画廊（上限 50 张）。安全过滤（`src/sanitize.ts`，212 行）与生成状态机（`src/main.ts`，含超时、取消、单次重试）质量明显高于普通 MVP。

但产品定位从「自用工具」变为「独立对外产品」后，暴露两处结构性缺口：

1. **首屏即劝退**：`index.html:18-33` 默认展开「模型设置」，要求陌生人先填三个技术字段才能看到任何价值；无 Key 时页面除示例文字外无任何可看、可导出、可玩的内容。
2. **产出带不走、传不出去**：`main.ts:389` 只导出 `image/svg+xml`，SVG 无法直接发到微信、朋友圈、抖音；无账号、无分享载体，纯前端下「攒用户」没有可观测路径。

### 2.2 要解决的问题

| 编号 | 问题 | 现状证据 |
|---|---|---|
| PB-01 | 无 Key 的访客零价值体验 | `main.ts:179-194` 三项前置校验直接拦截生成 |
| PB-02 | 配置错误发现太晚、报错不指向真因 | 仅生成时 `fetch` 报错，`api.ts:100-105` 统一为「网络没连上」，CORS 与断网无法区分 |
| PB-03 | 导出格式无法进入主流传播渠道 | `main.ts:391` 仅 SVG Blob |
| PB-04 | 新图覆盖旧图，未存画廊即永久丢失 | `main.ts:145` 直接 `innerHTML = safe` |
| PB-05 | 删除作品不可逆 | `main.ts:520` 直接 `removeFromGallery` |
| PB-06 | 「免费」表述与实际成本存在误导风险 | 站点无收费说明文案 |
| PB-07 | 无后端导致增长不可观测 | 全项目无统计、无账号、无上报 |

### 2.3 成功指标与口径

> 口径总则：所有指标均为**匿名聚合值**，统计周期按自然日，按匿名会话去重，不含已知爬虫与预渲染请求；**不上报 prompt 文本、API Key、Base URL、SVG 内容**。

| 指标 | 定义（口径） | 数据来源 | v0.3 目标值 | 说明 |
|---|---|---|---|---|
| M-01 首次可用率 | 首次进入站点后，在**未填写 Key 的前提下**完成至少 1 次「查看示例作品」或「导出 PNG」的匿名会话数 ÷ 首次访问匿名会话数 | 平台侧匿名页面事件 | ≥ 60%（目标值，待上线后建立基线） | 衡量 FR-01/07 是否解决 PB-01 |
| M-02 配置成功率 | 点击「测试连接」返回可用的匿名会话数 ÷ 点击过「测试连接」的匿名会话数 | 平台侧匿名事件（仅记成功/失败类别，不记端点值） | ≥ 50% | 衡量 FR-02；失败类别限定为 CORS/401/404/网络 四类 |
| M-03 导出率 | 导出 PNG/SVG/分享卡片的次数 ÷ 生成成功次数 | 平台侧匿名事件计数 | ≥ 40% | 衡量 PB-03；同一次生成多格式导出按次数计，不去重 |
| M-04 分享回流 | 由外链来源（referrer 非空且非本站域名）进入的匿名会话数 | 平台侧访问统计 | 建立基线即可，不设目标 | 纯前端**无法归因到具体作品**，见 14.2 遗留问题 |
| M-05 生成质量基线 | 评测集合法 SVG 率、可渲染率、危险节点数 | 本地人工评测（见 7.13 AI 六模块） | 合法 SVG ≥90%、可渲染 ≥95%、危险节点 = 0 | 非线上指标，每次改 prompt 或模型必跑 |

**明确不承诺**：注册数、留存率、付费转化（本期无账号、无付费、无服务端，物理上不可测）。

### 2.4 开源与作品集目标（v0.3.1 追加）

**目标**：项目公开在 GitHub，可作为简历中的可验证作品引用；希望通过自然传播获得 Star。

**路由变更留痕（多轮信号累积）**：

| 轮次 | 输入信号 | 路由结果 |
|---|---|---|
| R1 | 「检查产品待完善/拓展」 | 通用工具盘点 |
| R2 | 独立对外 / 纯前端 / BYOK 免费 | 面向普通用户的纯前端 AI 生成工具（+AI 六模块 / 数据合规 / 指标口径） |
| R3 | 简历、GitHub 地址、Star | **追加**「开源项目 / 开发者作品集」场景：双受众、仓库可展示性、社区治理清单；按「只增不减」，R2 已锁定的清单全部保留 |

**双受众与不同诉求**：

| 受众 | 看什么 | 决定什么 |
|---|---|---|
| U-01/U-02 普通使用者 | 在线 Demo 能不能零配置出图 | 会不会用、会不会分享 |
| U-04 开发者 / 招聘方（新增，画像为待确认假设） | README 能否 30 秒讲清问题与难点、代码是否有可验证的技术深度、Demo 是否真能跑 | 会不会点 Star、简历里这一条是否有说服力 |

**关键判断：Star 是结果，不是可设计的功能。** 因此：

- 允许：README 里一句克制的「欢迎 Star」、真实的技术说明、可复现的快速开始、Issue/PR 模板、持续更新的 CHANGELOG、公开在线 Demo。
- 禁止：**以奖励/功能解锁换 Star、批量刷 Star、产品内求 Star 弹窗、Star 门槛、诱导分享**（命中红线自检「不设计诱导分享、强制授权、虚假营销」；亦不符合 GitHub 社区规范）。
- 结论：v0.3 不新增任何「求 Star」功能，只在页脚放一个不打扰的源码入口（FR-14）。

**M-06 Star 数口径**：仓库公开后的累计 Star 数，来源为 GitHub 页面公开计数，统计周期为累计值、按仓库去重；不含 Fork 数、不含 Watch 数。**不设目标值**——Star 受传播渠道影响，不属于产品可控指标，仅作为观察项，不得据此倒推需求优先级。

**开源转化的真实前置依赖**：当前在线 Demo 无 Key 时看不到任何成品，招聘方点进去是空画布，这是 Star 转化的最大障碍。因此 **FR-01（免配置示例作品）从「降低普通用户门槛」升级为「作品集可展示性的前置条件」**，建议在对外宣传仓库之前先完成 FR-01，其次 FR-04（PNG 导出）。

**已确认的仓库事实（2026-11-06 核查）**：仓库 `https://github.com/1576584678/aigc-doodle-studio` 已存在且公开，`main` 分支 1 个提交 `13cc02d`，0 Star / 0 Fork，无描述、无 Website、无 Topics、无 Release。本轮补齐的门面物料见附录 F。

## 三、名词与术语定义

| 术语 | 定义 |
|---|---|
| BYOK | Bring Your Own Key，用户自备模型服务的 API Key；请求由**浏览器直连**用户填写的端点，本站不经手任何密钥与调用内容 |
| 免配置示例作品 | 随静态资源一同发布的预置 SVG 作品（内置、非模型生成），无需 Key 即可查看、下载、导出 PNG |
| 端点预设 | 若干常见的 OpenAI 兼容 Base URL 候选，供用户从下拉选择而非手填；**本站不验证、不背书、不代理**任何第三方端点 |
| 作品分享卡片 | 由前端 Canvas 合成的竖版 PNG，含作品图、描述文字、站点地址；纯本地生成，不上传 |
| 画布历史 | 本次会话内最近 N 张成功生成图的内存队列，仅防覆盖丢失，刷新即清空 |
| 平台侧匿名统计 | 静态托管平台自带的访问分析能力（如 Pages Web Analytics），**非自建后端、非第三方统计 SDK** |
| 危险节点 | `src/sanitize.ts` 中 `FORBIDDEN_TAGS` 及非 `ALLOWED_ATTRS` 属性所对应的 SVG 节点/属性 |

## 五、方案对比与选型说明

### 5.1 候选方案（针对「陌生人首屏零价值」+「攒用户不可观测」）

| 维度 | 方案 A：纯前端零配置体验层 + 平台侧匿名统计（推荐） | 方案 B：纯前端 + 第三方统计 SDK | 方案 C：轻量后端代理 + 账号 |
|---|---|---|---|
| 核心思路 | 内置示例作品让无 Key 访客也能完成「看→导出→分享」；用静态托管自带统计看匿名趋势 | 保留 BYOK，引入通用统计脚本做漏斗与事件追踪 | 服务端转发模型请求，可做试用额度、账号、作品分享页 |
| 实现成本 | 低 | 低 | 高 |
| 开发复杂度 | 低（不新增运行时依赖） | 低 | 高（鉴权、限流、密钥、存储、审核） |
| 用户体验 | 好：零门槛先体验，配置后置 | 中：首屏问题未解决 | 好：可免 Key 试用 |
| 风险 | 低 | **中高**：第三方脚本与明文 Key 同域，隐私卖点受损 | **高**：需购服务器、承担密钥与合规责任 |
| 上线时间 | 快（静态构建即发布） | 快 | 慢 |
| 与三条定位一致性 | 完全一致 | 部分违背（零采集） | 直接违背（不引入后端、BYOK） |

### 5.2 推荐结论

**推荐方案 A。** 理由：

1. 它是唯一同时满足「独立对外（降低陌生人门槛）」「纯前端（零服务器）」「零采集隐私」三条约束的方案。
2. 「攒用户」在纯前端下的可行动作只有两个：**让别人先看到价值**（示例作品）、**让作品自己带路**（分享卡片上的站点地址），两者都不需要服务端。
3. 方案 B 的第三方脚本会与 `localStorage` 中明文存放的 API Key 处于同一页面上下文，风险与「设置保存在本机、不会上传」的现有承诺（`index.html:32`）冲突。
4. 方案 C 被用户明确否决，不进入本期比较范围，仅在 A-05（用户拿不到可跨域端点）被证伪时重新评估。

**不选方案 B/C 的原因**见上表；方案 C 另需重新过定位评审，不在本 PRD 授权范围内。

### 5.3 演进路径

| 阶段 | 内容 | 进入下一阶段的触发条件 |
|---|---|---|
| v0.3（本期） | 补闭环：零配置体验、PNG 导出、画布历史、删除撤销、分享卡片、匿名统计 | M-01 ≥60% 且 M-03 ≥40%，连续 2 个自然周达标 |

## 六、用户角色与使用场景

### 6.1 用户画像（信息不足处标注为待确认假设）

| 角色 | 身份背景 | 核心目标 | 典型痛点 | 能力水平 | 备注 |

## 七、功能需求

> 状态词规范：必须（shall）/ 应该（should）/ 可以（may）/ 禁止（must not）。验收统一用 Given / When / Then。
> 每条需求标注来源：用户原话要点 / 问题编号 / 假设编号。

### FR-01 免配置示例作品与首屏引导（Must）

**来源**：A-01、PB-01、US-01

**描述**：随静态资源发布 6 张内置 SVG 示例作品（3 简笔画 + 3 火柴人），页面首屏右栏默认展示，无需 API Key 即可查看、下载 SVG、导出 PNG、生成分享卡片。左栏「模型设置」由默认展开改为默认收起；设置区上方增加一句话价值说明与「本站不收费」费用说明入口。

**业务规则**：

1. 内置示例必须（shall）经过与模型输出相同的 `sanitizeSvg` 过滤后再进入 DOM，禁止（must not）因为是自有资源而跳过过滤。
2. 示例作品必须（shall）标注「示例」标识，禁止（must not）与用户作品在视觉上混淆。
3. 无 Key 时点击「生成」必须（shall）给出「先看看示例，或填写自己的模型配置」的引导，而非仅红色报错；现有三项前置校验文案（`main.ts:181-194`）须改写。
4. 示例作品不占用画廊 50 张配额，不写入 `localStorage`。
5. 设置区收起状态可（may）记住用户上次选择，但不得因此隐藏费用说明。

**验收标准**：

- Given 全新浏览器会话、未填任何配置，When 打开首页，Then 右栏在 1 秒内显示 6 张示例作品且「设置」处于收起态，页面无任何报错文案。
- Given 无 Key 会话，When 点击任一示例作品并点「导出 PNG」，Then 生成可正常打开的非空 PNG 文件，且网络请求数为 0（无模型调用）。
- Given 无 Key 会话，When 点击「生成」按钮，Then 出现引导文案而不是「请先填写 API 地址」，且焦点不落到报错框。
- Given 示例 SVG 中被人为插入 `<script>` 或 `onload`，When 页面加载，Then 该节点被移除且控制台无脚本执行。

### FR-02 费用说明与隐私说明（Must）

**来源**：用户决策 3、PB-06、A-03、US-07

**描述**：在设置区与页脚提供静态说明文案，明确「本站不收费、不设账号；图片生成由你填写的模型服务完成，该服务可能向你收取调用费用，费用与本站无关」；明确「API Key、描述内容、作品仅保存在本机浏览器，本站无服务器、不接收、不存储」。

**业务规则**：

1. 页面禁止（must not）出现「完全免费」「零成本」「无限免费生成」等可能被理解为模型调用也免费的表述；统一表述为「本站不收费」。
2. 禁止（must not）使用「最」「第一」「顶级」等绝对化用语。
3. 必须（shall）保留现有「API Key 明文存放，公用电脑请勿保存」警示（`index.html:32`），不得因增加隐私说明而弱化。
4. 说明文案必须（shall）为静态文本，不引入任何外部脚本或远程字图资源。

**验收标准**：

- Given 任意会话，When 展开设置区，Then 可见费用说明与明文存放警示两处文案，且全文检索不含「完全免费」「零成本」。
- Given 任意会话，When 用浏览器开发者工具检查网络面板并完整生成一次，Then 除用户填写端点外，不存在向本站域名或其他统计域发起的携带 prompt / Key / SVG 的请求。

### FR-03 端点预设与连接自检（Must）

**来源**：PB-02、A-05、US-02、M-02

**描述**：Base URL 输入框旁提供「常用端点」下拉（用户选择后自动填入，始终保留手动输入能力）；新增「测试连接」按钮，以最小请求验证配置可用性，并按类别返回可操作的错误提示。

**业务规则**：

1. 预设项仅为常见的 OpenAI 兼容地址格式示例，本站不背书、不代理、不保证其可用性；下拉须标注「仅填地址，本站不验证第三方服务」。
2. 测试连接必须（shall）使用 `max_tokens` 最小化的请求，且禁止（must not）携带任何用户作品数据；测试产生的费用归属用户，文案须提示「测试会产生一次极小的模型调用」。
3. 错误分类必须（shall）至少区分：`CORS/网络被拦`、`401/403 密钥或权限`、`404 接口地址`、`429 限频`、`超时`、`其他`；现有 `httpUserMessage`（`api.ts:50-56`）须扩展。
4. CORS/网络类提示必须（shall）说明「浏览器直连要求该端点允许跨域，本站为纯前端无法代为转发」，并给出「换用支持跨域的端点」这一可行动作。
5. 测试连接禁止（must not）把 API Key 写入 URL、日志、`console` 或任何本地持久化之外的位置。
6. 测试连接期间按钮进入 busy 态并禁止重复点击，支持取消。

**验收标准**：

- Given 填入一个不可达地址，When 点击「测试连接」，Then 6 秒内返回明确的分类错误文案且不出现「正在生成」等误导状态。
- Given 填入 Key 错误的合法端点，When 点击「测试连接」，Then 返回 401/403 类提示，且状态区不出现任何 Key 片段。
- Given 测试进行中，When 连续点击按钮 3 次，Then 仅发出 1 次请求。
- Given 任意失败类别，When 查看文案，Then 每条都含至少一个用户可执行的下一步动作。

### FR-04 PNG 导出（Must）

**来源**：PB-03、US-03、M-03

**描述**：在现有「下载 SVG」旁新增「导出 PNG」，支持透明底 / 白底两种、1x / 2x / 4x 三种倍率，文件名含模式与时间戳。

**业务规则**：

1. 必须（shall）基于**已过滤的** `currentSvg` 渲染，禁止（must not）重新请求模型或读取未过滤字符串。
2. 渲染路径必须（shall）为：`sanitizeSvg(currentSvg)` → Blob（`image/svg+xml`）→ `Image` → `Canvas` → `toBlob('image/png')`；加载完成后必须（shall）`URL.revokeObjectURL`。
3. 白底模式必须（shall）先在 Canvas 填充 `#FFFFFF` 再绘制；透明底不得填充。
4. 输出尺寸必须（shall）为 `400 × 倍率`（viewBox 基准 400×400，`prompts.ts` 已约束）；当模型返回非 400 基准 viewBox 时，按 `viewBox` 实际宽高等比输出，禁止拉伸变形。
5. SVG 内含 `<text>` 时，导出结果可以（may）因系统字体差异与画布略有不同，需在说明中标注。
6. 导出失败必须（shall）降级为「下载 SVG」并明确提示，禁止静默失败。
7. 整个导出过程禁止（must not）产生任何网络请求。

**验收标准**：

- Given 一张成功生成的简笔画，When 选「透明底 2x」并导出，Then 得到 800×800 PNG，四角像素 alpha=0，主体像素非全透明。
- Given 同一张图，When 选「白底 4x」，Then 得到 1600×1600 PNG 且背景为纯白。
- Given 导出能力被模拟为失败（Canvas 抛错），When 点击导出，Then 提示可下载 SVG 且原有 SVG 下载按钮仍可用。
- Given 完整导出一次，When 检查网络面板，Then 新增请求数为 0。

### FR-05 画布历史（Must）

**来源**：PB-04、US-04

**描述**：会话内保存最近 5 张成功生成/查看的图（含 prompt、mode、SVG），画布下方提供缩略切换；新图不再覆盖丢失。

**业务规则**：

1. 历史必须（shall）仅存内存，禁止（must not）写入 `localStorage`（避免与 50 张配额、quota 逻辑耦合）。刷新页面后清空，文案须说明「仅本次会话有效，重要作品请存入画廊」。
2. 容量为 5，超出时丢弃最旧一张，且必须（shall）在丢弃前提示「较早的一张已移出本次历史，可先存入画廊」。
3. 每张历史项必须（shall）绑定其真实 `mode`（沿用 `currentSvgMode` 设计，`main.ts:45`），切换时同步更新画布 `aria-label` 与模式标签，但**不得**改动模式按钮的选中态（避免误导下一次生成）。
4. 从画廊点击查看作品必须（shall）作为一条新历史项加入，而非覆盖当前项。
5. 取消 / 超时 / 失败不得（must not）新增历史项，也不得清除已有历史。

**验收标准**：

- Given 连续成功生成 2 张，When 点击历史第 1 张，Then 画布恢复第 1 张且其 `aria-label` 与第 1 张的 prompt 一致。
- Given 连续成功生成 6 张，When 查看历史，Then 仅保留最新 5 张，且第 6 次生成前出现过丢弃提示。
- Given 已有 2 张历史，When 生成第 3 张时超时，Then 历史仍为 2 张且画布保留第 2 张。
- Given 刷新页面，When 查看历史，Then 为空并显示「仅本次会话有效」说明。

### FR-06 删除可撤销（Must）

**来源**：PB-05、US-05

**描述**：画廊删除后在 toast 中提供「撤销」，撤销窗口内可完整恢复作品及其原始排序位置。

**业务规则**：

1. 撤销窗口为 5 秒；窗口结束或用户进行其他写操作后，删除不可再撤销。
2. 撤销必须（shall）恢复 `id`、`ts`、原始索引位置，禁止（must not）生成新 id 或排到队首。
3. 删除后的焦点迁移逻辑（`main.ts:534-538`）必须（shall）保持不变；撤销按钮须可键盘聚焦。
4. 若撤销写入失败（quota），必须（shall）明确提示「恢复失败，作品未找回」，禁止静默。

**验收标准**：

- Given 画廊有 3 张，When 删除第 2 张并在 5 秒内点「撤销」，Then 恢复为原 3 张且顺序、`id`、`ts` 与删除前一致。
- Given 删除后超过 5 秒，When 查看 toast，Then 撤销入口已消失，作品保持删除。
- Given 删除操作，When 用键盘 Tab，Then 焦点可达撤销按钮且可见焦点环。

### FR-07 作品分享卡片（Must）

**来源**：PB-07、US-06、M-04

**描述**：新增「生成分享图」，由前端 Canvas 合成一张竖版 PNG：上方作品图、中部描述文字、下方站点地址与一句「本站不收费，模型自备」。

**业务规则**：

1. 卡片必须（shall）完全本地合成，禁止（must not）上传作品或调用任何短链/图片服务。
2. 站点地址必须（shall）取自 `location.origin` 的静态部署域名；本地开发（`localhost`）时降级为不显示地址，仅在文案中说明。
3. 卡片必须（shall）带「示例」或「生成」标识，避免他人误以为可交互。
4. **不加水印、不加二维码、不加诱导分享文案**；站点地址仅作来源标注。
5. 描述文字超过 2 行必须（shall）截断并以省略号结尾，禁止溢出卡片。
6. 卡片不得（must not）包含 API Key、Base URL、模型名等任何配置信息。
7. 分享回流无法归因到具体作品，须在文档中记为遗留问题（14.2）。

**验收标准**：

- Given 任一作品（含示例），When 点击「生成分享图」，Then 得到非空 PNG，含作品、描述、站点地址三部分，且不含 Key/URL 配置字段。
- Given `localhost` 环境，When 生成卡片，Then 不显示地址且无空白占位。
- Given 生成完整一张卡片，When 检查网络面板，Then 新增请求数为 0。

### FR-08 平台侧匿名统计（Should）

**来源**：PB-07、A-04、M-01~M-04

**描述**：在静态托管平台开启自带的匿名访问统计；站内仅通过前端触发**不含参数值**的事件名（如 `export_png`、`test_conn_ok`、`test_conn_fail_cors`）。

**业务规则**：

1. 禁止（must not）引入第三方统计 SDK 或任何外部脚本（见 5.2 理由）。
2. 事件属性禁止（must not）包含 prompt、Key、Base URL、Model、SVG、作品 id。
3. 若托管平台不提供统计能力（可绕过），本期可以（may）只保留访问量指标，M-01~M-03 记为「本期不可测」并列入遗留问题，不得伪造数据。
4. 必须（shall）在隐私说明中写明「仅统计匿名访问与操作次数，不采集输入内容」。

**验收标准**：

- Given 完成一次 PNG 导出，When 查看上报载荷，Then 仅含事件名 `export_png`，无 prompt / Key / SVG 字段。
- Given 禁用平台统计，When 使用全部功能，Then 无功能不可用、无报错。
- Given 任意页面，When 检查资源列表，Then 不存在第三方域名的脚本资源。

### FR-09 风格选择器（Should）

**来源**：M-05、生成质量

**描述**：在模式切换下方增加 3 档风格（极简线稿 / 圆润可爱 / 涂色线稿），选择后以附加约束拼接到 system prompt 末尾。

### FR-11 分段超时修复（Should）

**来源**：14.1 技术债（v0.2 `main.ts:47,224`）

**描述**：将 60 秒总上限改为「单次请求 45 秒 + 重试独立计时 + 总上限 90 秒」，避免首次请求耗尽预算后重试立即超时。

**验收标准**：

- Given 首次请求在 44 秒时失败，When 自动重试，Then 重试仍拥有完整 45 秒，且「正在重试一次」文案与实际行为一致。
- Given 用户取消或总上限到达，When 查看状态，Then 不出现「生成成功」且画布不更新。

### FR-12 `sanitize.ts` 单元测试（Should）

**来源**：14.1 技术债、FR-02 隐私承诺

**描述**：为白名单过滤建立不少于 20 条攻击向量与合法样本的自动化测试，纳入构建前置。

**验收标准**：

- Given 含 `<script>`、`foreignObject`、`onload`、`javascript:` 混淆写法、DOCTYPE/ENTITY、CDATA 注入、`data:` 协议等样本，When 运行测试，Then 全部被移除或拒绝，通过率 100%。
- Given 合法简笔画 SVG，When 运行测试，Then 过滤后仍可渲染且保留 `viewBox`、`xmlns`。

### FR-13 清除本机数据（Must）

**来源**：10.3 数据合规专项第 3/5 项、SEC-05、US-07

**描述**：在设置区提供「清除本机数据」入口，二次确认后清除 `aigc_doodle_settings` 与 `aigc_doodle_gallery` 两个 localStorage 键，并将内存中的画布历史与当前作品一并清空。

**业务规则**：

1. 必须（shall）二次确认，确认文案须明确列出「API Key、模型配置、全部画廊作品」三类将被删除且**不可恢复**。
2. 清除后必须（shall）回到初始态：设置输入框清空、画布回到示例作品空态、画廊计数为 `0 / 50`、历史为空、导出按钮禁用。
3. 清除范围限定为本站 `aigc_doodle_*` 前缀的全部 localStorage 键（覆盖 v0.2 现有两键与本期新增键），禁止（must not）扩大到其他站点数据或无关键。
4. 清除动作禁止（must not）产生网络请求；平台侧匿名统计只记一次不含参数值的 `clear_local_data` 事件（FR-08 口径）。
5. 与 FR-06 撤销窗口并存时：清除必须（shall）同时终止未结束的撤销窗口，避免撤销把已清除的作品写回。

**验收标准**：

- Given 本机已有 Key 与 3 张画廊作品，When 点「清除本机数据」并确认，Then 两个 localStorage 键均不存在，画廊显示 `0 / 50` 且 Key 输入框为空。
- Given 清除确认弹窗，When 点「取消」，Then 所有数据保持不变。
- Given 删除作品后 5 秒撤销窗口仍开启，When 执行清除，Then 撤销入口消失且刷新后作品仍为空。
- Given 执行清除，When 检查网络面板，Then 无携带数据的外发请求。

### FR-14 页脚源码入口（Must，本轮已实现）

**来源**：R3 开源与作品集目标、A-06、2.4

**描述**：页面页脚常驻一行费用/隐私说明（「本站不收费 · 模型与 API Key 由你自备 · 数据仅存本机」）与一个指向公开仓库的文本链接，不做弹窗、不阻断、不自动跳转。

**业务规则**：

1. 链接必须（shall）带 `target="_blank"` 与 `rel="noopener noreferrer"`。
2. 禁止（must not）出现求 Star 文案、倒计时、遮罩或以 Star 为条件的功能解锁。
3. 页脚禁止（must not）引入第三方脚本、远程字体或统计像素。
4. 移动端 760px 下不得（must not）横向溢出。

**验收标准**：

- Given 任意会话（含有无 Key），When 滚动到页脚，Then 可见说明文案与仓库链接，点击在新标签打开仓库且原页面状态不变。
- Given 完整使用一次生成，When 检查页面资源，Then 不存在由页脚引入的第三方域名请求。
- Given 375px 视口，When 查看页脚，Then 无横向滚动条。

### 7.13 AI 功能六模块专项（场景 26 必带清单）

> 本产品核心为大模型生成，确定性假设不成立，以下六模块为 PRD 必要组成。

**1）任务定义**：普通用户在「描述一句话 → 拿到可直接使用的简笔画」这一步，原先成本是手绘或找素材；AI 负责**直接产出终稿 SVG**（非草稿、非建议），人只做「接受 / 重试 / 导出」。

**2）输入与上下文契约**

| 项 | 约定 |
|---|---|
| 输入来源 | 用户文本（≤300 字）、模式、风格档、system prompt |
| 权限范围 | 仅用户本机；不读取任何服务端数据、不读取其他作品 |
| 缺失处理 | 缺 prompt → 停止并聚焦输入框；缺 Key/URL → 停止并引导示例或配置；缺 Model → 沿用 `api.ts:87` 中的默认模型名继续（v0.3 建议改为显式必填，避免隐式依赖） |
| 冲突裁决 | 以本次提交的 `currentMode` / 风格为准，不以画布上历史图的模式为准 |
| 超长输入 | `maxlength=300` 前置限制 + `submit()` 归一化空白后校验，超出停止 |

**3）输出契约**

| 项 | 约定 |
|---|---|
| 结构 | 单个 `<svg>` 根元素，`viewBox="0 0 400 400"`，`xmlns` 合法 |
| 必填 | 根元素、可渲染图元、`xmlns` |
| 禁止 | 解释文字、markdown 围栏、外链、脚本、事件属性、DOCTYPE/ENTITY、背景与阴影 |
| 证据形式 | 输出即产物，无引用原文需求；生成参数（model/mode/style/prompt）记入本地历史项以便复现 |
| 可编辑范围 | 用户可改 prompt 重试；本期不提供 SVG 源码编辑 |
| 后续去向 | 画布渲染 → PNG/SVG/分享卡片导出 → 可选存入画廊 |

**4）质量标准与验收样本**

| 维度 | 口径 | v0.3 目标值 |
|---|---|---|
| 事实正确 | 输出含用户描述主体（人工判定） | ≥ 85% |
| 格式合规 | `sanitizeSvg` 通过且含合法 `xmlns`/`viewBox` | ≥ 90% |
| 可渲染率 | 浏览器可直接渲染且非空白 | ≥ 95% |
| 来源可靠 | 危险节点数 | 0（硬底线） |
| 支持下一步 | 可成功导出 PNG | ≥ 95% |

评测集（**待建立，样本为设计稿非既有数据**）：20 条 prompt，覆盖常见（猫/杯子）、缺失信息（单字）、口径冲突（描述含多种主体）、超长（接近 300 字）、边界（含特殊字符/emoji）、拒答（明显违规描述）六类 × 2 模式 × 3 风格抽样；每样本登记「可接受 / 不可接受」条件。改 prompt、改模型默认值或改风格档时必须（shall）重跑。

**5）异常降级与人工接管**（禁止统一「系统繁忙」）

| 触发 | 降级策略 | 接管时携带 |
|---|---|---|
| 返回非 SVG / 解析失败 | 不重试；保留 prompt 与上一张图，提示换说法 | prompt、模式、风格、失败类别 |
| 低质量（空白/只有根节点） | 提供「再画一张」按钮，不覆盖历史 | 同上 |
| 网络/CORS/5xx | 单次重试；再失败给分类提示与示例入口 | 同上 |
| 超时 / 用户取消 | 保持状态机既有清理逻辑，不更新画布 | 同上 |
| 导出失败 | 降级到下载 SVG | 作品字符串 |
| 触发危险节点 | 直接拒绝渲染，记 `console.error`（不含 Key/prompt 原文） | 失败类别 |

**6）反馈与版本闭环（纯前端约束下）**：本地记录「生成成功 / 失败 / 取消 / 重试」计数，可（may）在「关于」页展示本机统计；每条历史项关联 `model`、`mode`、`style`、prompt 快照，支持复现。禁止（must not）上传任何反馈内容；跨版本效果对比依赖人工跑评测集，不依赖线上埋点。

**AI 行为约束三层**

| 层级 | 规则 |
|---|---|
| Always do | 过滤后渲染、生成参数记入历史、失败保留上一张 |
| Ask first | 覆盖当前画布（由历史机制兜底）、写入画廊（用户点「存入画廊」）、调用模型（用户点「生成」或「测试连接」） |
| Never do | 不经用户操作自动发模型请求；不把 Key/URL/prompt 写入 URL、日志、统计事件、分享卡片；不过滤前注入 DOM；不因重试丢弃用户 prompt |

## 九、业务流程与状态流转

### 9.1 生成状态机（在 v0.2 五态基础上保持不变，补充约束）

| 状态 | 进入条件 | 允许操作 | 迁出 |
|---|---|---|---|
| `idle` | 初始化 / 取消完成 / 错误后重新输入 | 生成、浏览示例、导出、存画廊 | → `generating` |
| `generating` | `submit()` 校验通过 | 取消；示例 chips 禁用 | → `success` / `error` / `cancelling` |
| `cancelling` | 用户点取消 | 无（重复点击吞掉） | → `idle` |
| `success` | 模型返回且 `cancelReason === null` | 导出、存画廊、切换历史、查看示例 | → `generating` |
| `error` | 超时 / 分类错误 / 用户重新输入前 | 重试、浏览示例、导出上一张 | → `idle` / `generating` |

新增约束：

1. `success` / `error` 态下画布必须（shall）保留上一张成功图，禁止清空；状态文案与画布内容须在视觉上可区分（例：`error` 时画布角标显示「上次成功结果」）。
2. 历史队列写操作只允许发生在 `success` 与「示例/画廊查看」路径，`cancelling` / `error` 一律不写（FR-05）。
3. 超时计时按 FR-11 改为分段，但「取消中任何 resolve 一律丢弃」（`main.ts:243`）的既有不变量不得改动。

### 9.2 导出流程

`sanitizeSvg(currentSvg)` → 构造 Blob → `createObjectURL` → `Image.onload` → 建 Canvas（400×倍率）→ 按底色填充 → `drawImage` → `toBlob(png)` → 触发下载 → `revokeObjectURL`。任一环节抛错 → 终止、释放 URL、提示并降级到 SVG 下载。

### 9.3 分享卡片合成流程

取当前作品（或示例）→ 过滤 → 转 `Image` → 建 1080×1440 Canvas → 分区绘制（作品区 / 描述区截断 / 来源区）→ `toBlob(png)` → 下载。全程零网络。

## 十一、权限与安全要求

## 十二、异常处理清单

| 编号 | 场景 | 用户可见反馈 | 系统行为 | 可恢复动作 |

```
│  ├─ 模型设置（默认收起）：Base URL + 端点预设下拉 / Key / Model / 测试连接 / 不保存 Key 选项 / 清除本机数据
│  ├─ 生成模式：简笔画 | 火柴人
│  ├─ 风格：极简线稿 | 圆润可爱 | 涂色线稿
│  ├─ 示例 prompt chips + 描述输入框 + 字数
│  └─ 生成按钮（状态：生成 / 取消）
└─ 右栏（产出区）
   ├─ 画布（空态展示内置示例作品墙，带「示例」角标）
   ├─ 画布历史缩略条（最近 5 张）
   ├─ 操作条：下载 SVG | 导出 PNG（底色/倍率）| 复制代码 | 存入画廊 | 生成分享图 | 打印/PDF
   └─ 画廊（50 张上限，筛选/删除 + 撤销 toast）
```

**关键页面线框思路**

| 页面区 | 布局思路 | 交互说明 |
|---|---|---|
| 空态画布 | 默认显示 6 张示例作品缩略，非纯文字占位 | 点示例即载入画布并标「示例」，可直接导出；无 Key 也能完成闭环 |
| 设置区 | 默认收起，展开后费用说明与明文警示置顶 | 预设下拉只填地址；测试连接用次要按钮，避免与「生成」抢注意力 |
| 导出面板 | 点击「导出 PNG」展开小面板选底色与倍率 | 选项本地记住；导出中禁用按钮；失败给降级入口 |
| 历史条 | 画布下方横向 5 格缩略 | 当前项高亮；悬停/聚焦显示 prompt；刷新后显示「仅本次会话有效」 |
| 删除撤销 toast | 现有 toast 区增加「撤销」按钮 | 5 秒倒计时可见；键盘可达；超时自动消失 |

**可用性检查**：核心任务（看到作品 → 导出）≤3 次关键操作 ✅；每个按钮有明确结果预期 ✅；四态（空/载/错/界）均有设计 ✅；危险操作（删除、清除本机数据）二次确认或撤销 ✅；焦点环沿用 `style.css:290` ✅；文案无歧义、无诱导 ✅。
